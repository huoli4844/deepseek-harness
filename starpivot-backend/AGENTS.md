# 元枢集成后台开发规则

本文件适用于本目录及所有子目录。每次写代码或迁移前先读本文件；在原工作区还必须先读[全局编码规则](../CODING_RULES.md)。本目录是与 `deepseek-harness-dev/` 并列的独立 Go 模块，后台源码、测试、契约和项目规则均放在本目录内。

## 模块与分层

- 使用 Go。入口 `cmd/starpivot-backend` 只负责读取配置、组装模块和管理进程生命周期；`internal/server` 负责 HTTP 服务运行；`internal/transport/httpapi` 负责 HTTP 路由和协议转换。
- 有实际业务需求时按领域新建 `internal/<业务域>/`：`domain` 放业务实体和不依赖基础设施的规则，`application` 放用例及其依赖接口，`repository` 实现持久化适配。依赖方向为 HTTP → 用例 → 领域，仓储适配器依赖用例接口和领域。处理器不写 SQL，领域和用例不依赖 HTTP、具体仓储或框架；依赖由入口组装。
- 源码文件最多 3000 行；新增 Go 文件最多 300 行，其中领域模型最多 250 行。函数最多 80 行，嵌套不超过 3 层。包头和导出符号写中文注释，工具指令保持原样。

## HTTP 命名与契约

- 新增或修改后端接口前，必须先在[元枢接口清单](../swagger/接口清单.md)中按业务用途检索，再到[原始 OpenAPI](../swagger/openapi.json)核对接口定义。
- Swagger 已有同一业务接口时，以现有定义为基线修订和复用。沿用 HTTP 方法、路径和 `operationId`，按实际需求补齐或修订参数、请求体、响应及鉴权说明，并保持现有调用兼容。Swagger 中没有对应接口时，按下文的路由、命名和契约规则新建。
- 独立应用新增接口使用 `/api/v1/apps/deepseek-harness/<资源>`，分段小写，多个单词用 `kebab-case`；集合资源用复数。使用 HTTP 方法表达常规增删改查；已有业务域的专用动作和参数名遵循该域 Swagger 约定。并入元枢前确认路径、方法和 `operationId` 不冲突。
- `operationId` 为小写 HTTP 方法 + 按路径顺序拼接各段，首字母大写并去掉连字符和参数花括号；保留对标接口中的参数下划线写法。例如 `GET /api/v1/apps/deepseek-harness/health` → `getApiV1AppsDeepseekHarnessHealth`，tag 为 `apps/deepseek-harness`。业务成功响应优先沿用 `code`、`message`、`data`，具体字段、返回码和鉴权以对标契约为准。
- 新增或修改 API 必须同步本服务的 `api/openapi.json` 和接口测试，说明权限、租户来源、输入输出及错误行为。平台接入复用元枢的身份和租户权限；禁止直接信任客户端传入的租户标识。无鉴权健康探针只返回进程存活，不返回依赖、配置或业务数据。

## 数据库与迁移

- 先查现有表和数据归属，能复用则不重复建表。`database/BENCHMARK.md` 只允许按表名定点查看，且样例数据不能替代真实 DDL。使用或修改已有表前，须确认列类型、约束、租户范围、所有权及写入权限。
- 每次新建表或变更数据库字段，都必须在工作区的 [数据库变更记录](../database/数据库变更记录.md) 中追加条目。字段变更包括新增、删除、重命名、修改类型或约束，以及仅修改字段备注。记录日期、目标数据库、表名、涉及字段、变更前后内容、变更原因及对应迁移文件（如有）。新建表须列出全部字段。
- 确需新表时，使用接收方认可的版本化迁移。表名、字段名沿对应业务域现有约定。表和**每个字段**必须在数据库备注中写明中文注释，包含主键、外键和审计字段。在同一迁移中执行 `COMMENT ON TABLE` 和 `COMMENT ON COLUMN`。表备注统一为「XXXXXXX 表」格式，业务名称加「表」字收尾，不追加其他说明文字。
- 状态、枚举、标志位字段的中文注释必须用「值=含义」格式逐一列出可存值及含义；布尔字段统一为「true=启用，false=不启用」式的肯定/否定写法（如 `true=已删除，false=未删除`）；如允许 `NULL` 或有默认值，也须写明含义。数据库约束（如 `CHECK` 或原生枚举）、Go 定义和 API 文档必须与注释一致；改变枚举须同时更新这些位置。存量表仅调整本工作区新建或编辑过的表与字段，不改其他系统的表。
- 后台运行配置按用户确认的策略连接云端业务库；测试必须使用本地隔离数据库，不直连云端业务库。迁移不随服务启动自动执行，正式表结构变更通过版本化迁移并由获准的维护流程实施。业务查询必须绑定经鉴权确定的租户并参数化；不硬编码账号、口令或生产连接串。

## 交付门禁

- 执行 Go 格式检查、`go vet ./...`、`go test ./...` 和 `go build ./...`；HTTP 变更覆盖成功、错误方法和未知路径，涉及业务时额外覆盖鉴权、跨租户拒绝及失败路径。
- 提交迁移前在隔离数据库演练，检查数据库元数据中每个新字段的中文注释和状态值说明。缺失即不交付。
- 更新 README，并在工作区日志留档；生产部署或合并前由元枢确认最终模块路径、路由挂载、鉴权适配和迁移归属。
