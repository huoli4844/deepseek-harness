# @deepseek-ai/dsh-client-ui-voice-conversation

## 摘要

独立的连续语音对话插件：点一次麦克风后保持监听，按自然停顿自动断句、自动识别并发送；助手回答结束后自动朗读，用户一开口立刻打断朗读。

与自带的语音输入插件（`@deepseek-ai/dsh-experimental-client-ui-voice-input`）互不覆盖：

- 自带语音输入占用 `conversation.input.activity`（单占位），本插件占用右侧控制区 `conversation.input.right` 与状态条 `conversation.input.dock`。
- 自带语音输入是「按一次、说一句、转成草稿」；本插件是「常开监听、自动发送、朗读回答」。
- 两者各自持有自己的 `getUserMedia` 流与文案命名空间，彼此不引用对方的运行时值。

## 使用方式

1. 在插件列表中启用本插件（桌面 profile 的 `cordis.patch.yml` 已插入 `ui-voice-conversation` 行）。
2. 模型选择器旁出现电话图标；点击后允许麦克风权限，进入监听。
3. 说完一句话停顿约 0.7 秒，插件自动识别并发送。
4. 助手回答结束后自动朗读；朗读期间直接说话即可打断并开始下一句。
5. 再次点击按钮（或状态条上的「结束语音对话」）退出。

语音识别复用现有 `remote.speech`，需要先启用自带的语音输入 bundle 并完成模型准备；未就绪时按识别失败提示。

## Model Experience

模型在连续语音对话中收到的是普通用户消息（识别文本），没有额外的协议字段或工具调用。语音层只在浏览器侧工作：

- 识别文本经 `inputActions.insertText` 写入草稿后立即 `submit()`，因此模型看到的消息与手动输入一致。
- 模型回答被原样朗读；朗读不改变消息内容，也不产生新的回合。
- 输入框被占用（提交中或上一回合仍在回答）时，插件不会插话发送，只会保留最近一次识别文本并继续监听。

## 已知限制

- 语音合成使用浏览器 `speechSynthesis`，可用性与音色取决于操作系统语音包；不可用时不朗读，其余流程照常。
- 断句采用能量阈值 VAD，嘈杂环境下可能需要重新开始一次会话。
- 目前不提供「先说一句再确认发送」的中间模式，识别到文本即发送。
