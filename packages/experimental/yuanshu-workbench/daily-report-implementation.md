# 工作记录实现说明

每个技能一个目录，以 `SKILL.md` 为入口。当前包随工作台一起分发 `daily-report/`，宿主注册到原生 skills 服务，因此用户可在工作台助理中说“整理我今天的日报”。技能不能自行授予数据权限，也没有直接提交工具。

实现目录与边界：

| 目录 | 职责 |
| --- | --- |
| `skills/yuanshu-work-report/` | 日报与周报的工作流程与真实完成情况的归纳规则 |
| `src/plugins/yuanshu-work-evidence/` | 工作依据读取、会话账号归属验证 |
| `src/plugins/yuanshu-work-records/` | 已授权表单契约、本人日报查询、确定性保存适配 |
| `src/plugins/yuanshu-business-forms/` | 人工确认状态机、临时凭证、超时重试和回执 |
| `src/business-forms/` | 共享领域契约、受限 A2UI 消息模板 |
| `src/client/modules/business-forms/` | 数据层、纯视图模型、表单组件、交互容器 |

这些是同一工作记录能力包内的独立模块目录，目前不分别发布 npm 包，也不声称能独立下载安装到工作台。安装、升级与卸载仍由工作台所属插件生命周期统一管理。今后需要独立分发时，可以保留这些模块边界提取为插件包。

## 实际执行流程

1. 当前企业凭证请求本地业务服务的日报 `schema`，由身份服务验证真实用户与当前租户。
2. 工作台先绑定空白会话，再向会话发送用户消息。归属记入宿主会话日志；历史无归属会话不自动认领，改建新会话。助理会话缓存按后台返回的账号与租户分区。
3. 模型加载 `daily-report`，调用 `work_evidence_today`。只枚举相同账号、已绑定、活跃的工作台会话，只取北京时间当日的可见用户正文、助理正文与工具结果。失败工具和中断输出带独立结果标记；不读取系统提示、思维过程或任意本地文件。
4. 模型调用 `work_records_open_daily_report`，只提供五项正文及实际取得的出处引用。宿主查询本人当日已存日报的版本，已提交或已有未确认表单时拒绝覆盖。
5. 宿主产生固定白名单的 A2UI 子集消息；浏览器验证组件、绑定与动作完全匹配本地目录后打开弹窗。模型不能插入 URL、JavaScript、SQL、用户 ID、租户 ID 或审计时间。
6. 用户修改正文并点击“保存草稿”或“确认提交”，浏览器经同源人工路由把最终正文直接交给业务插件。模型不再次解释、转换或提交。
7. 后台重新验证用户及租户，在同一事务内检查版本、最近请求幂等、提交锁定，并产生审计时间。成功回读后才显示已保存或已提交。模型可通过 `work_records_daily_report_status` 读取真实回执。

## 表单协议范围

实现 `surfaceUpdate`、`dataModelUpdate`、`beginRendering` 三种消息结构，组件只开放 `Column`、`Text`、`TextField`、`Button`。这是日报专用的 A2UI v0.8 消息子集及本地目录，标签使用工作台 locale key，不是完整标准目录或通用第三方 A2UI 客户端。新业务须显式扩展白名单、字段映射、动作处理和测试，不能向渲染器传入任意模型 JSON。

## 边界与恢复

- **依据范围不完整**：当前只覆盖已验证且活跃的本人工作台会话，最多返回 100 条依据，每条最多 4000 字符。其他历史会话、离线工作与外部成果尚未自动全面采集，表单明确提醒人工补齐。
- **日报是独立资源**：不把个人日报塞进项目报告或周报。后台使用 `tsk_daily_work_reports`，不访问公司的经营汇总接口。
- **确认不是沙箱边界**：这里保证日报插件没有模型提交动作。若平台同时授予模型任意终端、数据库或通用 HTTP 能力，它们仍须通过平台能力治理与后台鉴权独立约束，不能仅靠技能提示保证整个平台安全。
- **短期租约**：浏览器每 45 秒重新通过后台验证账号；宿主租约 120 秒有效，真正保存时后台重新鉴权。凭证只在宿主内存，不进入模型输出、会话记录或应用日志。
- **临时表单**：30 分钟到期；宿主重启清除临时表单。已写入后台的日报不受影响。重新整理会读取已有版本。
- **网络结果不确定**：保留最终正文、请求标识和动作，暂时冻结编辑，只重试完全相同的请求；后台返回明确冲突时取消本表单并重新整理。最近一次请求的幂等记录不等于无限期保存所有历史请求。
- **后台不可用**：不阻断原生助理的新对话，但不能复用未经验证的旧会话，也不能启动日报表单。
- **部署前提**：后台维护流程先执行 `starpivot-backend/migrations/0009_daily_work_reports.sql`，然后重启本地业务服务和工作台。迁移不随服务启动自动执行，不在生产库写测试数据。

客户端测试：`tests/daily-runtime.spec.ts`、`tests/daily-owner.spec.ts`、`tests/daily-form.client.spec.tsx`。后台测试：`internal/dailyreport/repository/*_test.go`、`internal/transport/httpapi/daily_reports_test.go`。数据库集成测试要求显式设置回环地址的 `DSH_DAILY_TEST_DATABASE_URL`，只创建、销毁独立的一次性测试库。
