# 元枢业务智能体开发规则

本目录维护元枢工作台业务智能体的开发约定与登记索引。每个智能体在 `agents/<agent-id>/` 建一个独立目录，`agent-id` 使用小写英文与连字符，统一以 `yuanshu-` 开头。此目录保存智能体的业务定义和验收资料；可安装的 Agent preset 与业务插件仍按 DSH 现有组合包机制交付，不把本目录当作新的运行时或包管理器。

## 目录与交付

- 每个智能体目录至少有 `README.md`，记录业务目标、适用岗位、触发语义、输入和输出、所需技能与插件、数据范围、人工确认点、失败处理、验收案例及版本。涉及固定格式文件时，记录模板及字段版本的维护位置。
- 新建或更名智能体时，同步更新[智能体总览](智能体包总览.md)，登记 ID、目录、职责、依赖技能、交付组合包及维护入口。未实现的智能体不得登记为已可安装。
- 需要独立安装和转交的智能体，在 `packages/experimental/yuanshu-<agent-name>/` 建组合包，以 `@deepseek-ai/dsh-agent-preset` 声明 preset，并按[实验包规则](../../AGENTS.md)登记包。`agents/<agent-id>/` 中注明对应包名与 preset ID；二者不能仅靠目录存在而自动被发现。按 DSH 的[组合声明规范](../../../preset/agent-preset/skills/dsh-doc/references/compositions.md)制作和验证补丁。
- 可复用的员工业务流程放在[技能目录](../skills/AGENTS.md)，按业务插件的能力实现放在对应 `yuanshu-` 插件包或工作台现有业务模块。智能体目录不复制技能正文、接口实现或敏感数据。

## 职责与执行

1. Agent preset 明确模型可见的技能、工具、提示词与委托能力。普通工作台助手自动委托某智能体时，要有可辨认的触发范围、允许的 preset、调用方身份与失败反馈；安装 preset 本身不代表已经配置自动路由。
2. 每项读、写、导出和委托操作由执行端按当前租户、员工身份、角色及数据范围验权。提示词、技能文本、界面隐藏字段或模型自述不能充当权限控制。权限无法确认时停止该操作。
3. 技能写业务流程、复核方式和异常处理，不携带 API 地址、字段、凭据或后台连接逻辑。插件宿主通过授权接口取数并把有界、已裁剪的结果交给 Agent；敏感原始值只在获授权的服务端处理。
4. 模型可提出分类、权重、依据和文字分析；需要精确复算的金额、工时、指标、汇总与导出字段由版本化规则和确定性程序计算。低置信度、缺口和规则冲突进入人工复核，人工覆盖记录操作者、原因与时间。
5. 多步骤运行持久记录任务 ID、输入快照、规则版本、模型建议、复核结果与输出版本。重试使用幂等键；中断后先查任务状态，未知结果不宣称成功，也不重复写入。
6. 定时运行需记录触发、成功、失败与补跑结果。数据源为空、覆盖度不足或对账失败时给出可处理的状态；不要生成标为已完成的报告。

## 固定输出与验收

- Excel 等交付物使用受版本管理的模板：固定工作表名称与顺序、列名与顺序、数据类型、单位、公式或计算来源、显示格式和权限版本。Agent 只能提供模板允许的文字内容，不临时增删字段。
- 每份输出标注统计租户与时间范围、数据截止时间、数据快照、规则版本、模板版本和覆盖度。缺少必需字段、权限或校验结果时停止发布；修改模板或口径时升级版本并说明兼容性。
- 敏感字段按服务端授权投影分版本输出。带工时和分摊金额的个人明细可能推算时薪，不能只删去“时薪”列就当作脱敏版。下载和查询应留审计记录，组合包不得携带真实员工数据、薪资、密钥或令牌。
- 验收覆盖同一快照重复运行的一致性、跨月归属、缺报和人工调整、权限拒绝、失败恢复、文件结构与汇总对账。每个智能体目录写明自己的基准数据与通过条件；新增行为按仓库测试和文档门禁验证。

开发前仍须遵守[工作区编码规则](../../../../../CODING_RULES.md)、[Harness 架构](../../../../docs/architecture.md)和涉及目录的现有 `AGENTS.md`。
