# 元枢员工技能包开发规则

工作台随包发布的员工技能放在本目录。元枢自定义技能名称统一以 `yuanshu-` 开头，使用小写英文和连字符。目录名、`SKILL.md` 的 `name`、宿主注册名称和英文斜杠调用名使用同一个标识，中文展示名和中文调用词使用业务名称。在宿主注册技能并验证打包后可发现，流程写法可参考[工作报告](yuanshu-work-report/SKILL.md)。

本目录必须维护[技能包总览](技能包总览.md)。每条记录至少包含技能名称、目录、功能描述、适用岗位或场景和维护入口；新建技能时必须在同一变更中更新总览，已有技能缺少登记时应补齐，不得只新增 `SKILL.md` 而遗漏登记。

1. 除技能发现所需的名称和简介外，技能包只描述员工业务流程。写清适用岗位、使用场景、允许处理的业务内容、步骤、人工确认点、结果及异常处理。使用员工看得到的业务名称。
2. 本规则覆盖技能正文、README、示例、附件、配置以及随包发布的所有文件。严禁编写或附带任何连接后台服务或数据库的逻辑，严禁以脚本、命令、第三方依赖或委托其他工具的方式代为连接。
3. 严禁披露 API 地址、路径、请求方法、请求或响应字段、样例报文、内部工具标识、数据库表名与列名、凭据和连接配置。禁止通过链接、截图、日志或附件间接提供上述信息。后台接入及接口契约由插件宿主和后台服务维护，技术资料保存在技能目录之外。
4. 流程可以描述“打开草稿，请本人核对”，并区分已保存、已提交、已取消与失败。发布前逐项审阅实际随包文件，确认只包含业务流程或开发规则，且无连接逻辑或接口细节。

5. 技能触发的表单保存或提交必须等待工作台报告操作完成。只有收到成功回执后才能告知成功或关闭表单；失败时要求本人检查保留的内容，并按界面提供的安全方式重试。
6. 技能涉及数据录入时，只使用对应业务表及字段备注、当前服务端契约已经定义的字段和允许取值（包括 JSON 子字段）。技能不得创造字段、枚举、状态含义或默认值；与实际表结构不一致时先修正插件/API 契约。
7. 登记类技能优先让员工选择下载模板、上传表格或用文字描述。由插件给出必填项、校验上传内容并检查重复；文字描述只提取已有信息，未知项由员工补齐。统一打开 A2UI 复核表单，经本人确认后才写入。登记失败时保留表单，收到明确成功回执并由本人确认后关闭。
8. 字段备注以「值=含义」列出固定选项时，技能流程使用插件提供的下拉框。中文界面显示中文含义，用户表述能唯一匹配时预选，不能确认时交给用户选择。插件按正式契约校验并提交原值，技术映射保存在技能包之外。
9. 通用办理流程以工作台当前的能力目录和授权结果为准。每次发起或继续任何访问或改变企业数据的操作时，包括读取、查询、导出、新增、修改、删除和审批，先按具体动作核对当前员工在所选租户的数据范围及操作权限。权限明确拒绝或暂时无法确认时停止，授权通过后才准备资料、查重或打开表单。服务列表或业务对象变化由宿主同步，同一流程继续使用原技能。
10. 通用业务技能按工作台当前提供的字段和动作定义请求生成 A2UI 复核表单。固定模板统一外观和交互，业务对象与字段随运行时的动作定义变化。同一业务流程继续使用原技能。
