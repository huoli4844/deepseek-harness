# 工作报告

1. 根据用户的请求选择个人日报、个人周报或项目周报。未指定报告类型时先问清。使用北京时间计算日期，周报采用周一到周日的自然周。
2. 核对当前企业账号和本人报告的读取权限。新建前先查询今天的日报或本自然周的周报。查询失败或权限无法核实时停止新建，并说明情况。
3. 查到已提交的报告，告知员工对应日期或周期、已提交状态和可用的提交时间，并展示已保存的正文。查到已保存的草稿，提示「已保存草稿，尚未提交」并展示正文。员工明确要求继续编辑或提交草稿时，核对登记权限并打开原草稿进行复核。
4. 确认没有已有记录且本人有登记权限后，再整理可访问的工作依据。日报区分已完成、进行中、后续计划、风险和支持需求。周报按项目整理进展、事项、风险、下周计划和支持需求。项目唯一匹配时可预填，其余由本人选定。离线工作由本人补充。
5. 由本人在复核表单中保存、确认提交或取消。以工作台回执为准。遇到冲突时重新查询已有报告，按最新状态展示正文。明确失败时保留输入供本人修正。

## 项目周报

1. 用户明确要求整理项目周报时，先确认目标周期。查询本人本周已提交的日报、个人周报以及工作台提供的本地工作日志和对话依据。把已有个人周报作为项目进展的来源之一，不因个人周报已提交而跳过项目周报。清楚说明可用来源范围，不声称读取了实际未提供的对话或记录。
2. 根据近期工作依据整理涉及的项目，向用户列出项目并确认范围。询问只写用户指定的项目，还是逐一填写全部涉及项目。项目无法唯一确认时请用户选择，不自行归属。
3. 按用户确认的项目和正式服务字段定义整理本周进展、完成工作、下周计划、问题风险、支持需求及服务要求的其他内容。字段以工作台返回的字段定义为准；其中 key_metrics 由后台契约声明但当前模板不采集，需要向员工说明。区分已证实事实、用户补充和未知信息，不编造指标或状态。若服务未提供完整字段定义、有效权限或可核验的成功回执，说明缺少能力并停止写入。
4. 内容整理后询问用户要导出 Excel 汇总表，还是逐个项目打开 A2UI 复核。Excel 只导出、不写入后台；需要提交时仍走 A2UI 逐份确认。仅在工作台提供可验证的 Excel 导出能力时生成文件；否则明确告知不可导出，并由用户选择是否改用 A2UI。
5. A2UI 模式按项目逐个展示完整内容，由用户逐份确认。每次确认后等待该项目的后台操作完成及成功回执。成功时给出短暂成功提示后进入下一项目；失败时保留当前内容，在同一窗口显示可理解的错误并等待用户处理，不能提前提交下一项目。取消时停止后续写入并汇总已成功和未完成项目。
6. 全部项目处理完后汇总成功、失败、取消和未处理项。不得把个人周报的保存状态当成项目周报保存状态，也不得以请求发出代替成功回执。
