# A2UI 固定弹窗模板

本目录是元枢弹窗的开发模板来源。[通用确认](confirm.v1.json)用于确认单项操作，[内容编辑](edit.v1.json)用于新建、修改和预填草稿。JSON 描述固定布局和业务可填槽位，供插件开发时绑定。现有日报的 A2UI v0.8 消息生成方式见 [a2ui.ts](../a2ui.ts)。

| 项目 | 统一约定 |
|---|---|
| 外观 | 复用业务表单弹窗和平台组件。工作台内使用当前主题和文字大小，原生对话使用宿主主题和字号。标题、字段、输入控件及按钮沿用平台字体。宽度由模板指定并受视口限制。标题与页脚固定，长正文独立滚动。窄窗口下多列表单改为单列。 |
| 内容 | 标题和按钮绑定本地文案 key。编辑字段顺序、类型、必填项及校验由云端契约或兼容插件声明，同一业务在各端使用同一份声明。模型只能填写获准的数据字段。 |
| 交互 | 操作按钮从左至右遵循模板顺序。取消不写入，保存草稿与正式提交各自绑定独立的已注册动作。请求期间阻止重复操作，失败时保留输入并展示错误。 |
| 键盘 | 打开后焦点移入弹窗，确认类默认聚焦取消，编辑类聚焦首个可编辑字段。Tab 在窗内循环，Esc 按取消处理，关闭后焦点返回触发处。 |
| 接入 | 宿主按云端契约或兼容插件定义绑定模板版本、字段白名单、文案和动作，将允许的内容映射为宿主支持的 A2UI 消息。宿主负责标题、关闭和焦点。禁止将模板 JSON 当作消息直接发送，禁止执行模型传入的动作或样式。 |
| 特殊弹窗 | 两个模板均无法描述业务交互时，在此目录新增具名模板，说明适用场景并链接到本页。改变已有字段顺序或动作语义时新增版本，调用方显式选用。 |

验收时用同一业务输入在 macOS 和 Windows 对照字段顺序、按钮顺序、窄窗滚动、取消及写入回执。

字段或动作名末尾的 `?` 表示可选槽位。`dialogGutter` 取工作台的弹窗边距 token。确认模板的 `confirm` 必须绑定当前操作的具体动词和目标。

## 视觉风格契约

所有由 A2UI、云端契约或字段定义生成的界面，必须复用工作台现有外壳与控件。样式由渲染器负责，消息和字段定义不得携带颜色、间距、内联样式或任意类名。

| 维度 | 统一取值 |
|---|---|
| 主题 | 工作台子树由 `.theme`（深色）和 `.theme.light` 覆盖 DSH 令牌；弹窗挂载在 body，必须经 `BusinessFormModal` 继承工作台字号与文字色 |
| 字体 | `--dsw-font-family`；正文 `--dsh-content-font-size`（13px），行高 1.6，标题 600；字号随 `--work-font-scale` 缩放（小 0.92、标准 1、大 1.08） |
| 颜色 | 文字 `--dsw-alias-label-primary/secondary`；控件背景 `--dsw-alias-bg-layer-1`；边框 `--work-line` 或 `--dsw-alias-border-l4`；焦点 `--dsw-alias-state-business-primary`；禁止硬编码色值 |
| 间距 | 表单区 `--dsw-business-form-space-1/2/3`（4/8/12px）；字段网格 gap 10px 12px |
| 圆角 | 控件 `--dsw-radius-sm`；文本域和卡片 `--dsw-radius-md` |
| 控件 | 字符串/数字用 `Input`；多行用 `textarea`（至少 3 行、可纵向缩放）；日期用 `type=date`；枚举用 `select`；布尔用 `checkbox`；未支持字段只显示弱化说明，不渲染输入框 |
| 布局 | 标题与页脚固定，正文独立滚动；字段默认两列，视口 ≤520px 改单列；跨列字段占满整行 |
| 状态 | 错误 `role=alert` 并使用错误色；成功提示 2 秒后关闭；提交中禁用操作；契约不支持的字段使用 `--work-muted` 说明 |

生成界面的唯一入口是 `BusinessFormModal`（外壳、标题、关闭、焦点、宽度）+ `DynamicRecordFields`（字段网格与控件）+ 平台 `Button`（页脚）。`DynamicRecordDialog` 是参考实现。固定流程（如项目周报逐份复核）可以在同一外壳内自定义正文布局，但控件样式必须取自 `business-forms.module.css` 或对应共享 module。新增渲染器必须复用这些外壳与样式：不得直接输出无类名的 `input/textarea/select`，不得内联 `style`，不得把样式写进 A2UI 消息或字段定义。

## 从云端目录自动接入新增业务

云端发布符合以下约定的新增接口后，工作台在登录刷新或五分钟目录缓存到期后的下一次查询识别它。业务使用通用编辑模板，不需要在客户端登记业务名称。对话中的新增动作、别名、字段、权限和回执均由云端目录提供。

| 发布内容 | 工作台读取约定 |
|---|---|
| 动作 | 在业务应用的静态路径 `POST` 上声明唯一 `operationId`，以及 `x-yuanshu-workbench-create` 对象。对象包含 `version: 1`、业务名称 `title`、业务别名或已核实的表名 `aliases`、员工权限编码 `permission` 和成功回执标识的字段名 `receipt_field`。权限编码须实际出现在员工有效权限接口中。 |
| 请求 | 用 `properties` 声明 JSON 对象的字段，可使用本地对象 Schema 引用。声明了 `required` 时在提交前校验。未声明时由后端校验，明确拒绝后在原弹窗提示并保留编辑值。当前模板读取普通字符串、日期、整数、数字及带正式标签的枚举。字段显示名称优先使用 `title`，其次是 `description` 的首段，最后使用字段名。枚举用 `enum` 声明原值，并用 `x-enum-labels` 提供从原值到显示名称的映射。 |
| 回执 | 新增成功后，以 2xx 返回 JSON。标识字段位于 `data` 对象内或响应根部，使用非空字符串或正整数。采用 `code` 包装时，成功业务码为 0、200 或 201。 |
| 权限与提交 | 宿主核对当前账号、租户和动作权限，再打开表单。人工保存时复核动作与权限，按字段定义转换后端所需的类型。后台必须按该租户和员工身份完成鉴权。 |

当前通用入口适用于普通单条登记。需要路径参数、嵌套字段、附件、联动查重或特殊回执的接口保留专用流程，直到通用契约支持对应能力。契约缺失、字段定义不受支持或权限无法验证时，工作台不会开放该动作的通用提交。

查询、导出、修改、删除、审批等业务接口，可在对应的方法与路径上发布 `x-yuanshu-workbench-permission`，值为当前员工资料中使用的有效权限编码。宿主在能力查询中标记授权结果，执行仍须通过对应的业务工具，并由服务端按租户和数据范围校验。菜单权限目录用于核对编码，不能替代员工的授权结果。

固定路径的新增接口也可以使用现有操作权限声明和 OpenAPI 成功响应。用 `x-yuanshu-workbench-permission` 绑定有效权限编码，在成功响应根对象或 `data` 对象中声明必返的字符串或整数 `id`。满足这两个条件时可以直接使用通用表单。

桌面源码模式可用 `DSH_YUANSHU_FORM_PREVIEW=1 ./start-desktop.sh` 开启联调预览。会话仍需绑定企业账号。该模式只读 Swagger，为有明确字段且受模板支持的静态新增接口生成表单。模拟保存仅在宿主内存中校验字段并确认完成，不发出业务写请求，也不生成真实回执。退出后按普通方式启动即恢复正式模式。
