# 日报场景实现与权限边界

本文是插件开发资料，位于技能包之外。员工技能只描述业务流程，不包含下文的接口、内部动作和数据字段。

## 目录与分工

| 目录 | 职责 |
| --- | --- |
| `skills/daily-report/` | 员工业务流程，不附带连接逻辑或技术契约 |
| `src/plugins/work-evidence/` | 已绑定账号的工作依据读取、会话归属验证 |
| `src/plugins/work-journal/` | 本地事件采集、按北京时间半天归档与恢复 |
| `src/plugins/work-records/` | 后台授权表单契约、本人日报查询与保存适配 |
| `src/plugins/business-forms/` | 人工确认状态机、短期凭证、幂等重试和真实回执 |
| `src/business-forms/templates/` | 固定模板，日报显式选择 `edit.v1` |
| `src/business-forms/a2ui.ts` | 白名单字段与注册动作的受限消息映射 |
| `src/client/modules/business-forms/` | 数据层、纯视图模型、展示组件、容器 |

这些是工作台插件内部的独立模块，随同一个插件包启停，当前不是分别安装的 npm 插件。未来确需单独分发时再提取独立包。

## 实际流程

1. 原生对话和工作台右下角助理共用日报弹窗入口。已登录时，输入区等待首次账号绑定完成，最长等待 8 秒；失败后普通聊天可以继续。宿主验证用户及租户，为尚无消息的新会话写入账号归属。已有消息且无归属的旧会话仍保留历史，可点「新建日报会话」；新会话通过账号校验后才切换过去。临时绑定失败可在原会话重试。
2. 工作依据合并同账号的半天归档和活跃会话日志，默认北京时间当天。指定最近两小时等回看范围时按实际时长过滤，可跨零点。归档保留事项发起标记、工具名和成功或失败状态、宿主确认的工作区内相对成果路径，不存聊天正文、工具参数、工具返回正文或文件内容。整理时不调用远端 MCP、知识库或经营数据接口。查询成功、计划和模型建议不能单独作为已交付的依据。
3. 模型提供获准的正文及实际取得的出处。宿主核验出处并读取本人当日现有日报；已有草稿时完整保留人工正文及出处，已提交时拒绝编辑。
4. 插件绑定 `edit.v1` 版本、宽度、字段与动作顺序，转换为 A2UI 子集消息；浏览器只接受匹配本地白名单的表面。焦点进入首个可编辑字段，标题与页脚固定，正文滚动。
5. 用户修改后点击保存或提交。最终正文直接进入同源人工回调，模型不再次解释、转换或提交。取消不写后台。
6. 后台重新鉴权，限定用户、租户与工作日，在事务内检查版本、最近请求幂等、状态与审计时间。成功回读后才提示已保存或已提交。

内部能力为 `work_evidence_today`、`work_records_open_daily_report`、`work_records_daily_report_status`。没有模型保存、提交工具。这些绑定归插件维护，不写入员工技能包。

## 接口与授权

| 方法与路径 | 范围 |
| --- | --- |
| `GET /api/v1/apps/deepseek-harness/daily-reports/schema` | 可信本人、当前租户和可编辑字段 |
| `GET /api/v1/apps/deepseek-harness/daily-reports/{date}` | 本人指定工作日的日报 |
| `PUT /api/v1/apps/deepseek-harness/daily-reports/{date}` | 人工确认正文，保存或原子提交 |

浏览器只访问 `/yuanshu-workbench/daily-report-runtime` 同源宿主通道。宿主使用当前员工身份访问配置的本地业务服务，不接收模型提供的地址、SQL、身份或审计时间。Go 后台使用 `public.tsk_daily_work_reports`，不混用项目报告或周报。完整契约见后台 `api/daily-reports.openapi.json`。插件和技能脚本均不直连数据库。

## 正常与受限验收

- 正常：整理只打开弹窗，人工确认后才写入；保存内容必须与人工最终正文一致。
- 已有草稿：重新整理保留人工正文、出处和当前版本，不能被模型新草稿覆盖。
- 身份：其他用户或租户不能认领已有账号会话；同账号另一会话也不能确认此表单。登录凭证变化后停止使用旧草稿。
- 状态：草稿可编辑，已提交正文锁定，重复请求不刷新提交时间。
- 网络：结果未知时保留最终正文和原请求，冻结编辑，仅重试相同幂等请求。明确冲突时取消并重新整理。
- 降级：后台读取失败不能伪装成“没有工作记录”。可基于已验证本地证据和固定字段生成未同步草稿；该草稿不写后台、不声称已有服务器草稿。保存连接中断时冻结最终正文并保留同一幂等请求，恢复后重试；身份、权限或版本冲突必须停止。

当前实现状态：保存结果未知时已经冻结内容并支持同一请求重试；同时在浏览器本地按账号指纹缓存最终正文、业务日期、出处和幂等请求号，不保存登录令牌。日报接口恢复且账号重新验证后，工作台会提醒用户重新核对；用户可选择重新整理或放弃本地副本。跨重启自动重放原提交请求和完整的本地待同步队列属于下一阶段，当前不会静默提交。
- 卸载：撤销路由、技能提供器与工具，清除内存凭证和临时表单。

## 限制与部署

采用 A2UI v0.8 的 `surfaceUpdate`、`dataModelUpdate`、`beginRendering` 消息结构，只开放本地 `Column`、`Text`、`TextField`、`Button` 及工作台文案。这是受限实现，不是完整第三方标准目录客户端。模板文件不能当作消息直接发送，模型不能扩充动作、样式或组件。

归档位于 `$DSH_HOME/workbench-journal/<租户 ID>/<员工 ID>/`（默认根目录 `~/.dsh`）。有记录才生成文件，例如 `2026-11-26-AM.jsonl` 和 `2026-11-26-PM.jsonl`，按事件发生时的北京时间 00:00、12:00 切换。宿主每 2 秒批量写盘，会话检查点与工作台卸载时也会刷新；日报读取前即时刷盘。重启后首次验证账号时，最多检查最近创建的 100 个本地会话并补齐其中最近 48 小时的归属记录，按会话和事件序号去重。

每次整理最多返回最近 100 条依据，活跃会话正文每条最多 4000 字符。普通业务页面的增删改、工作台外操作和文件服务器同步尚未接入。浏览器每 45 秒重新鉴权，宿主租约 120 秒有效，保存时后台再次鉴权。凭证只在宿主内存，不进入模型、会话或归档。临时表单 30 分钟有效，重启失效，已保存日报仍在后台。

日报没有模型提交动作，但通用终端、HTTP、数据库等能力若另被授予，仍须通过平台沙箱与后台权限独立约束，不能只靠技能提示保证安全。

维护流程先执行 `starpivot-backend/migrations/0009_daily_work_reports.sql`，再重启业务服务和工作台；启动不自动迁移，本次未修改云端业务库。前端验证入口为 `tests/daily-runtime.spec.ts`、`tests/daily-owner.spec.ts`、`tests/daily-form.client.spec.tsx`。后台真实 HTTP 与 PostgreSQL 测试只使用回环地址下的一次性隔离库，不写业务库或备份库。
