# 元枢工作台 · 运营者视角界面规格（占位符版）

> 版本：v0.1 · 日期：2026-11-23 · 状态：设计稿，未落代码
> 适用范围：少仕租户（shaoshi）的公司运营者视角，作为 `design.zh.md` / `integration-design.zh.md` 的界面层补充
> 重要声明：本文所有数值均为占位符，不是线上真实数据。占位规则见第 2 节。

---

## 1. 设计目标与现状

### 1.1 目标

让公司运营者**一屏回答三个问题**：公司现在怎么样、哪里出了问题、今天要拍什么板。主线为「结果 → 异常 → 项目 → 职能 → 证据」，而不是按岗位堆图表。

### 1.2 现状事实（核查结论）

| 维度 | 事实 |
|---|---|
| 接口规模 | shaoshi 共 308 个操作，其中 211 个挂在 `projects/{code}/` 下，天然是「按项目记账」视角，缺公司级入口 |
| 契约质量 | 308/308 响应是 `RuntimeRouteResponse`（`data` 任意），144 个写操作是 `GenericJsonRequest`，**零 query 参数**（无分页/筛选/排序） |
| 前端现状 | `packages/experimental/client-yuanshu-workbench`，11 个分区；Live 模式只接 5 个 MCP 工具（profile / home / briefing / decisions / position） |
| 前端已解析字段 | `platform-home.ts`：`risks`（id, title, risk_code, project_name, handler_name, deadline, status）、`my_tasks`（id, name, code, project_name, owner_name, plan_end, status）、`projects`（name）、`milestones`（name）、`kpis`（label, value, reason 等）、`items`（title 等）、`workflows`（label 等） |
| 权限约束 | 工作台投影是岗位视图而非权限系统；`tenant_data_query_records` 的聚合默认使用**已发布指标**，当前 8 条指标定义全为 draft、`kpi_results` 为空表 |
| 数据缺口 | 无公司级汇总接口、无时序快照、无报表导出、无统一审批状态机（唯一显式决策接口为受控文档版本 `decision`）、无告警接口 |

### 1.3 数据支撑度三档

设计稿中每个元素必须归入以下三档之一，并在界面上标注对应状态标签：

- **A 档 · 接口就绪**（标签：`接口就绪 · 待抓样`）
  - `workbench_briefing`：逾期决策、延迟采购、检验积压、开放质量异常四类计数（`briefing.go:202-302`）
  - `workbench_home`：`risks` / `my_tasks` / `projects` / `milestones`
  - `workbench_decisions`：决策记录列表
  - `workbench_profile` / `workbench_position` / `workbench_navigator`：身份、岗位、导航
- **B 档 · 有路径无契约**（标签：`字段待定`）
  - `stage-tree` / `gates` / `risks` / `finance-summary` / `service-summary` / `quality-exceptions` / `delivery-followups`
  - 路径存在但响应泛化，前端字段映射待后端类型化后确认
- **C 档 · 无接口**（标签：`待接入`）
  - 公司级四张 KPI（合同总额、任务按期完成率、来料一次合格率、发运及时率）
  - 微趋势时序、证据关联、建议方案、审批按钮

## 2. 占位符规范（强制）

### 2.1 数值占位

- 统一显示为 `— — —`，使用次要文字色（`--color-text-tertiary`），保持 24px 字号与原版式一致。
- 列表项占位统一显示为 `— 事项 1`、`— 事项 2`，不编造业务标题。
- **禁止**：填 0、填任何具体数字、填伪真实百分比、把 Demo 模式的 fixture 数值搬到 Live 模式。

### 2.2 状态标签

每个占位元素必须**同时**显示：状态标签 + 数据来源。

| 标签 | 含义 | 样式 | 后续动作 |
|---|---|---|---|
| `接口就绪 · 待抓样` | A 档，接口与字段已定义，只差线上真实数据 | success 底色 | 抓一次线上投影即可替换 |
| `字段待定` | B 档，路径有、契约泛化 | info 底色 | 后端补类型化 schema 后映射 |
| `待接入` | C 档，当前无接口 | warning 底色 | 新增聚合投影 / 指标发布后接入 |

### 2.3 卡片四要素

每张 KPI 卡固定包含：指标名、数值（或占位）、口径说明、来源 + 状态标签。口径缺失时显示「口径定义待发布」，不得从缺失公式推导。

## 3. 全局框架

### 3.1 侧栏导航（四组）

| 分组 | 分区 | 数据支撑 |
|---|---|---|
| 经营视角 | 经营总览、异常与决策、项目穿透 | A 档为主，C 档占位 |
| 职能运营 | 质量 · 供应 · 交付 · 财务 | B / C 档，占位为主 |
| 我的工作 | 今日工作、我的任务、日程、通知、工作群 | A 档（home tasks / milestones） |
| 资源 | 文件与资料、工作方法 | 知识/SOP 工具，另行设计 |

> 现有 Live 模式过滤规则（`project-operations` 仅项目经理、`position-operations` 仅非项目经理）导致公司运营者没有全局页。运营者视角应补齐这部分能力，但不改变原岗位视图的过滤逻辑。
>
> **导航接入方式（实现约束）**：五屏是平铺进上述"经营视角"分组的五个**一级菜单项**，共用工作台原有侧栏；
> 内容区组件（`OperatorWorkbench`）只接收当前屏幕 id 并渲染内容，**不得自带侧栏或标题栏**。
> 严禁在经营总览里再嵌一层二级菜单——那会形成两套导航、同名菜单，用户无从判断该点哪个。

### 3.2 顶栏

左侧：当前页面标题。右侧固定三件事：当前角色（来自 `workbench_profile`）、时间范围（默认本季度）、数据更新时间（无字段时显示「新鲜度未提供」）。

## 4. 五屏规格

### 4.1 经营总览（首屏）

**布局**：4 张 KPI 卡 + 2 个队列 + 1 条数据健康提示。不做图表墙。

**4 张 KPI 卡（全部 C 档占位）**

| 指标 | 占位口径 | 预期来源 | 接入条件 |
|---|---|---|---|
| 合同总额 | 已签合同含税金额 | `fin_contracts` | 需公司级聚合投影 + 指标发布 |
| 任务按期完成率 | 实际完成 ≤ 计划完成 | `prj_project_tasks` | 同上；注意与平台 `tsk_collab_tasks` 口径分离 |
| 来料一次合格率 | 合格数 / 检验数 | `qwh_quality_inspections` | 同上 |
| 发运及时率 | 按承诺日期发运 | 需先建接口 | shaoshi 无 shipment 路径，只有 `deliveries` |

**四类异常队列（A 档）**：逾期决策 / 延迟采购 / 检验积压 / 开放质量异常，来源 `workbench_briefing`，计数占位为 `—`，每条带来源与新鲜度；点击下钻到记录。

**今日决策（A 档）**：来源 `workbench_decisions`，显示标题 / 影响 / 建议字段位；点击进决策中心。

**数据健康提示**：固定显示「库存周转、售后工单、KPI 达成率暂无经确认的数据 → 指标待办」，不占位、不造零值。

### 4.2 异常与决策

**布局**：左筛选队列 + 右详情抽屉。

- 筛选条：全部 / 逾期决策 / 延迟采购 / 检验积压 / 质量异常，计数来自 `workbench_briefing`（A 档）。
- 队列项：严重度色点（红=超期、琥珀=待处理）、事项名、超期天数、来源工具名。
- 详情抽屉四段：关键事实（B 档，字段待定）、关联证据（C 档，需 `workbench_records` + `ontology_context` 适配）、建议方案（C 档，Agent 组装产物）、操作按钮（C 档，少仕督办 Action 需适配）。
- 操作按钮先以禁用态占位，标注「治理链路待适配」；落地时走 `action_preflight → request → approve → execute`。

### 4.3 项目穿透

**布局**：项目组合卡 → 单项目 360 摘要 → 明细下钻。

- 组合卡（A 档）：来自 `workbench_home.projects`，显示名称、阶段、进度、风险标签；进度字段当前未解析，标注 `字段待定`。
- 单项目 360 六个面板（B 档）：阶段树 / 门禁 / 风险 / 财务 / 质量 / 下一动作，对应 `stage-tree` / `gates` / `risks` / `finance-summary` / `quality-exceptions` / `decision-queue`。面板内数值一律占位，标注来源路径。
- 全局只加载 `projects` 主数据，选中项目后才按需拉明细，避免一次性铺开 211 个项目接口。

### 4.4 职能专题

质量 / 供应 / 交付 / 财务四本账。当前全部为 B / C 档：保留页面骨架与筛选控件，列表区用占位行，标注对应表名（如 `qwh_quality_inspections`、`pur_purchase_orders`、`srv_shipments`、`fin_contracts`）。后端补出类型化投影后逐域替换。

### 4.5 证据与追溯

`workbench_records` 提供受岗位/领域/页码/关键词/状态约束的读取，作为下钻终点。关联证据链（决策 → 记录 → 受控文档 → 知识引用）当前需 `ontology_context` / `ontology_objects_query` 适配少仕绑定，先以占位链接展示，标注「证据链待适配」。

## 6. 接口替换路径

### P0 · 零后端改造
- 首屏四类异常、今日决策、风险/任务/项目列表接真实投影（A 档抓样替换）。
- 全部 C 档维持占位，不新增接口。

### P1 · 后端受治理投影
- 发布指标定义（将 8 条 draft 审核发布），`kpi_results` 产出行，替换四张 KPI 卡。
- 为 B 档路径补类型化响应 schema；为列表接口补分页 / 筛选 / 排序 query 参数。
- 统一审批状态机（submit / approve / reject）覆盖付款申请、验收、工程变更。

### P2 · 数据与能力补齐
- 建公司级聚合看板接口、时序快照、事件游标接口。
- 补库存余额台账、售后工单 OCR 录入。
- 补报表导出、告警规则、MES 资源可枚举元数据。

## 7. 验收要点

1. Live 模式下不出现任何编造数值；每个 `— — —` 都带状态标签与来源。
2. A 档元素在拿到线上投影后可逐项替换，替换不需要改版式。
3. Demo 模式与 Live 模式的占位规则一致，不出现「Demo 有数、Live 空列表」的误导。
4. 每张卡的下钻目标明确；无下钻目标的元素标注「暂不可下钻」。
5. 不伪造成功：操作按钮在 Action 适配前保持禁用态。
