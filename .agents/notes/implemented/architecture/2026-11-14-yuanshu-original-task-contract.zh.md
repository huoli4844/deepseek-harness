# Agent Note: 元枢任务引用保留原执行事实

Status: implemented

[English](2026-11-14-yuanshu-original-task-contract.md) | 中文

## Problem

客户端如果按资产名称选择恢复和取消操作，就必须理解平台的各个执行引擎。增加一份任务账本，还会对完成状态、授权和审批产生互相竞争的结论。

## Decision

元枢为持久化业务执行返回显式 `task_ref`。客户端保存该引用，调用平台的统一任务操作。服务端逐次适配原领域操作，并检查当前权限。引用用于定位已有执行，不赋予权限。

[工作台](../../../../packages/client/ui-yuanshu-chat/README.zh.md)仅恢复属于当前用户和租户的引用。取消操作按平台声明的可用操作和终态显示。在授权查询确认结果前，不确定的结果保持不确定。

[企业工具](../../../../packages/yuanshu/yuanshu-tool/README.zh.md)和网关在默认发现时隐藏兼容别名。迁移期间，显式且有权限的旧调用仍可使用。用户按发布的业务标题选择能力，稳定调用名称和修订继续沿用既有含义。

## Alternatives considered

**按资产名称前缀选择操作。** 未采用，因为新增执行引擎会要求客户端增加分支，且场景内部标识可能不同于作为事实依据的 Run 标识。

**把执行和审批状态复制到 DSH。** 未采用，因为权限、执行事实和工作流继续由平台负责。DSH 保存定位引用和展示状态。

**立即移除旧操作。** 未采用，因为保存的会话和回退配置仍会使用它们。默认发现可以优先使用统一操作，同时保留显式兼容调用的授权检查。

## Consequences

客户端依赖平台契约，不再依赖引擎命名规则。不支持的操作明确失败。部署先安装后台契约，再升级客户端；回退保留原记录，不重放业务写入。每次请求仍须携带既有用户授权和租户绑定。

## Testing

组件测试覆盖业务标题、恢复时不重提执行以及取消按钮的可见性。集成测试通过 DSH 官方 MCP Client 验证原 PostgreSQL 记录、Docker 结果、当前权限和工作流审批。浏览器验收覆盖独立审批人、刷新恢复和统一契约取消。
