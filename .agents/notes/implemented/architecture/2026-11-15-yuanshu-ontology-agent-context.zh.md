# Agent Note: DSH 使用元枢本体上下文

Status: implemented

[English](2026-11-15-yuanshu-ontology-agent-context.md) | 中文

## 问题

DSH 通过 MCP 发现元枢工具，但 Agent 需要先理解已发布本体的对象和字段语义，才能组织有效查询。读取集合还需要明确且有权访问的空间，运行审计样本也不能替代文档引用。

## 决策

目录调用从 `ontology_spaces` 开始，按所选空间读取集合和发布版本。Agent 先用固定发布版本调用 `ontology_context`，再执行查询。上下文包含对象字段、关系和实际支持的查询能力，不包含数据源和表映射。已有消费方绑定和平台行策略继续裁决每次查询。

`ontology_evidence` 表示按版本聚合的运行轨迹、Action 执行和治理账本样本。它不是知识证据；文档引用仍使用 `knowledge_search`。请求 Schema 按真实处理器 DTO 生成，并拒绝废弃的 `evidence_id` 字段。

## 已考虑的替代方案

**只返回资产引用。** Agent 无法据此理解字段含义或构造对象查询。发布快照中的语义描述让 Agent 直接组织查询，已有运行时继续校验。

**由 DSH 复制本体和权限定义。** 两份定义会漂移，并扩大客户端责任。元枢继续维护发布版本、消费方绑定和行策略，DSH 仅消费当前授权目录。

## 影响

发现结果增加了本体使用指引，所选工具和结果仍记录在原会话中。目录读取和数据查询保持不同职责；理解发布语义不会自动获得行数据权限。

## 验证

服务端定向测试使用隔离租户夹具执行原集合、上下文和证据处理器，校验输入和输出 Schema，并拒绝跨租户版本读取。DSH 测试覆盖 SDK 参数转发、网关校验、工作台空间切换及过期响应隔离。本记录不代表客户数据金标或生产发布验收通过。
